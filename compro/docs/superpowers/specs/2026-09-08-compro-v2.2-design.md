# Compro Plugin v2.2.0 — Design Specification

> **Status:** Draft — Menunggu review dan persetujuan sebelum implementasi
> **Author:** Audit Session 2026-09-08
> **Upgrade dari:** v2.1.0 → v2.2.0
> **Scope:** 12 perbaikan arsitektur, konten, visual, dan DX

---

## 1. Latar Belakang

Plugin Compro v2.1.0 sudah berfungsi end-to-end (Writer → Reviewer → Builder → Publisher), tetapi audit mendeteksi beberapa kelemahan:

1. **Bug kritis:** Agent langsung membaca file input tanpa konfirmasi user
2. **Broken images:** 2 dari 7 slide punya SVG yang gagal dimuat karena tidak di-inline
3. **Hallucinated data:** Kontak di output terakhir dikarang (tidak ada di input docs)
4. **Konten repetitif:** Tagline dan deskripsi Hero mengulang kata yang sama
5. **Visual monoton:** Semua problem cards pakai ikon identik
6. **Tidak ada resumability:** Pipeline harus diulang dari awal jika gagal di tengah

Versi 2.2.0 memperbaiki semua temuan di atas sekaligus memperkuat kualitas output.

## 3. Desain Detail Per Perubahan

### A1. User Intent Gate (Gate -1)

**Masalah:** Orchestrator langsung masuk Gate 0 (periksa file) tanpa menanyakan user. Jika file dari run sebelumnya kebetulan ada, agent langsung memproses tanpa izin.

**Desain:**

Tambahkan step baru **sebelum** Gate 0 di `skills/compro/SKILL.md`:

```markdown
0. **Gate -1 — User Intent & Input Confirmation:**
   - SEBELUM membaca, mencari, atau mengakses file apapun, tanyakan:
     > "Saya akan membuat Company Profile slide deck. Untuk memulai,
     > saya membutuhkan 3 dokumen input:
     > 1. `business-knowledge-base.md` — data faktual bisnis
     > 2. `business-audit-report.md` — analisis pasar & kompetitor
     > 3. `brand-story-guide.md` — panduan brand & tone of voice
     >
     > Apakah kamu sudah menyiapkan dokumen ini? Jika ya, di mana
     > lokasinya? Jika belum, aku bisa membantu membuatnya dari brief."
   - **HARD GATE:** DILARANG membaca file apapun sebelum user menjawab.
   - Jika user menunjuk file yang ada, tampilkan nama + ukuran file
     dan konfirmasi: "Apakah ini dokumen yang benar untuk sesi ini?"
   - Baru setelah user mengonfirmasi, salin/link file ke `input/`
     dan lanjut ke Gate 0.
```

**Constraint:**
- Gate -1 WAJIB dijalankan setiap kali plugin dipanggil, tanpa exception
- Tidak boleh ada shortcut "auto-detect" yang bypass gate ini

### A2. Enforce Inline SVG — Zero Broken Images

**Masalah:** Builder menghasilkan SVG sebagai file terpisah dan me-reference via `<img src="assets/...">`. Saat disajikan via HTTP server sederhana, path relatif bisa gagal — menyebabkan broken images.

**Desain:**

Tambahkan aturan baru di `skills/builder/SKILL.md` section "Smart Asset Pipeline":

```markdown
### 3a. Inline SVG Enforcement Rule
- **SEMUA aset SVG yang di-generate builder** (hero banner, ecosystem diagram,
  smartphone mockup, icon badges, closing banner) WAJIB di-inline langsung
  ke dalam HTML sebagai tag `<svg>`, BUKAN sebagai `<img src="assets/file.svg">`.
- File SVG terpisah di `assets/` tetap disimpan sebagai arsip/backup,
  tetapi HTML TIDAK BOLEH me-reference mereka.
- Satu-satunya `<img>` yang dibolehkan adalah:
  - Gambar dari CDN eksternal (URL `https://`)
  - Gambar raster yang disediakan user (PNG/JPG) yang memang harus
    jadi file terpisah
- **Post-build self-check:** Setelah menulis `index.html`, scan semua
  tag `<img`. Jika ada yang me-reference path lokal relatif
  (`src="assets/..."` atau `src="./..."`), itu adalah ERROR —
  baca file tersebut, inline isinya sebagai `<svg>`, dan hapus tag `<img>`.
```

**Constraint:**
- Aturan ini berlaku retroaktif: jika builder menemukan output lama dengan `<img src="assets/*.svg">`, harus di-fix saat rebuild

### A3. Visual Self-Check Post-Build

**Masalah:** Tidak ada mekanisme verifikasi visual setelah build. Builder tidak pernah "melihat" output-nya sendiri.

**Desain:**

Tambahkan phase baru di Orchestrator antara Phase 3 dan Phase 4:

```markdown
3b. **Phase 3b — Visual Self-Check:**
    - Buka `compros/<slug>/index.html` di browser.
    - Navigasi setiap slide dan periksa:
      1. Apakah ada gambar/ikon yang broken (placeholder kosong)?
      2. Apakah teks terpotong atau overflow di luar slide boundary?
      3. Apakah layout sesuai archetype yang dimaksud?
      4. Apakah semua `<img>` me-render dengan benar?
    - Jika ditemukan masalah:
      - Untuk broken SVG → inline ulang SVG ke HTML
      - Untuk overflow teks → potong konten atau split slide
      - Untuk layout salah → re-render section yang bermasalah
    - Catat hasil verifikasi di `reports/build.log` dengan format:
      ```
      [VISUAL CHECK] Slide 1 (Hero): OK
      [VISUAL CHECK] Slide 2 (Problem): OK
      [VISUAL CHECK] Slide 3 (Solution): FIX — overflow text trimmed
      ```
    - Phase 3b bersifat **blocking**: tidak boleh lanjut ke Phase 4
      jika ada slide yang masih bermasalah.
```

Juga tambahkan di Builder SKILL.md section baru "Post-Build Verification".

### B4. No Verbatim Repetition Rule

**Masalah:** Di output terakhir, Hero slide punya tagline dan paragraph body yang mengulang kata yang sama persis verbatim.

**Desain:**

Tambahkan aturan baru di `skills/writer/SKILL.md` section "Aturan Penulisan & Chunking":

```markdown
5. **No Verbatim Repetition:**
   - Dalam satu slide, setiap elemen teks (tagline, deskripsi, bullet point)
     HARUS menyampaikan informasi yang BERBEDA satu sama lain.
   - **Tagline** = hook pendek yang punchy, maksimal 1-2 kalimat.
   - **Deskripsi** = elaborasi value proposition yang menambah detail BARU,
     BUKAN mengulang kata-kata tagline.
   - **Statistik** = angka faktual yang memperkuat, bukan memarafrase tagline.
   - Rule of thumb: jika >40% kata di deskripsi sama dengan tagline, itu repetisi.
   - Pelanggaran aturan ini merupakan alasan reviewer mengeluarkan REVISION_REQUIRED.
```

### B5. Contact Factual Check + Content Deduplication

**Masalah:** (1) Reviewer tidak memeriksa pengulangan teks; (2) Kontak di output terakhir dikarang — nomor `+62 812-8888-0199` dan email `halo@venturopro.id` tidak ada di input docs manapun.

**Desain:**

Tambahkan 2 checklist item baru di `skills/reviewer/SKILL.md` section "Checklist Audit Reviewer":

```markdown
5. **Content Deduplication:**
   - Tidak ada kalimat atau frasa yang diulang verbatim antar elemen
     pada slide yang sama (tagline ≠ deskripsi, heading ≠ body).
   - Jika repetisi >40% terdeteksi pada slide manapun → REVISION_REQUIRED
     dengan catatan "Repetisi verbatim pada Slide X: [elemen A] vs [elemen B]".

6. **Contact Information Factual Check:**
   - Semua informasi kontak (nomor telepon, email, website, alamat, nama PIC)
     WAJIB bersumber langsung dari `business-knowledge-base.md`.
   - Cross-check setiap item kontak di Slide CTA/Contact terhadap
     data kontak di input docs.
   - Jika input docs TIDAK menyediakan kontak tertentu:
     - Gunakan placeholder eksplisit: `[Nomor WhatsApp]`, `[Email Resmi]`,
       `[Alamat Kantor]`
     - Tandai di review report: "Kontak X belum tersedia di input docs —
       menggunakan placeholder"
   - **DILARANG KERAS** mengarang/memfabrikasi nomor telepon, email,
     atau alamat yang tidak ada di dokumen sumber. Ini merupakan
     pelanggaran Zero Hallucination yang serius.
```

### B6. Extended Slide Structure (7 → 10 slide, opsional)

**Masalah:** Struktur 7 slide saat ini generik. Company profile premium biasanya punya slide differentiator dan social proof.

**Desain:**

Update "Struktur Urutan Slide Standar" di `skills/writer/SKILL.md`:

```markdown
3. **Struktur Urutan Slide Standar (Diperluas):**
   - **Slide 1 (Hero):** `# [Nama Perusahaan]` + Tagline + Ringkasan + 2-3 statistik kunci.
   - **Slide 2 (Problem):** `# Masalah yang Dihadapi` + 3 poin masalah utama.
   - **Slide 3 (Solution):** `# Solusi & Nilai Tambah` + penjelasan solusi utama.
   - **Slide 4 (Key Features):** `# Layanan Unggulan` + card-based features.
   - **Slide 5 (Ecosystem):** `# Arsitektur & Ekosistem` + diagram platform/alur.
     *(Opsional — hanya jika bisnis punya platform/ekosistem yang layak divisualisasikan)*
   - **Slide 6 (Traction & Proof):** `# Pencapaian & Bukti` + metrik + device mockup.
   - **Slide 7 (Why Choose Us):** `# Mengapa Kami` + tabel pembanding atau
     differentiator vs alternatif/kompetitor.
     *(Opsional — hanya jika data kompetitor tersedia di business-audit-report.md)*
   - **Slide 8 (Social Proof):** `# Testimoni & Kepercayaan` + quotes klien
     atau logo trust badges.
     *(Opsional — hanya jika testimoni/portofolio klien tersedia di input docs)*
   - **Slide 9 (Pricing):** `# Paket & Kerjasama` (opsional jika ada pricing).
   - **Slide 10 (CTA & Contact):** `# Hubungi Kami` + kontak lengkap.
```

**Constraint:**
- Slide 5, 7, dan 8 bersifat **opsional** — hanya dihasilkan jika data relevan tersedia di input docs
- Writer TIDAK BOLEH mengarang data untuk mengisi slide opsional
- Jika semua slide opsional di-skip, output tetap 7 slide (sama seperti v2.1)
- Ini berarti output minimal 7 slide, maksimal 10 slide

Juga perlu update di Builder SKILL.md:
- Tambahkan archetype baru: **Differentiator Table Archetype** dan **Social Proof / Testimonial Archetype**
- Update di `references/visual-hierarchy.md` dengan layout komposisi baru

### C7. Problem Card Icon Variation

**Masalah:** Semua 3 problem cards di output terakhir pakai ikon SVG yang identik (triangle alert).

**Desain:**

Tambahkan aturan di `skills/builder/SKILL.md` section slide Problem:

```markdown
### Problem Card Icon Variation Rule
- Setiap problem card WAJIB menggunakan ikon SVG Lucide-style yang BERBEDA
  dan semantically RELEVAN dengan masalah yang digambarkan.
- Panduan pemilihan ikon:
  | Kategori Masalah | Ikon yang Sesuai |
  |------------------|------------------|
  | Biaya / Finansial | TrendingUp, DollarSign, CreditCard |
  | Konsistensi / Kualitas | Palette, Layers, ShieldOff |
  | Workflow / Fragmentasi | Puzzle, GitBranch, Shuffle |
  | Kecepatan / Waktu | Clock, Hourglass, Timer |
  | Keamanan / Risiko | ShieldAlert, Lock, AlertOctagon |
  | Skalabilitas | BarChart, Activity, Scale |
- DILARANG menggunakan ikon yang sama untuk >1 problem card dalam satu deck.
- Jika tidak yakin kategori masalah, default ke ikon yang paling deskriptif
  berdasarkan kata kunci di heading card.
```

### C8. Dynamic Brand Color Extraction

**Masalah:** Builder punya mekanisme HSL theming tapi tidak ada instruksi eksplisit untuk mengekstrak warna brand dari input docs. Warna selalu default Venturo Teal.

**Desain:**

Tambahkan langkah baru di `skills/builder/SKILL.md` section "Langkah Kerja Kompilasi Slide":

```markdown
### 1a. Brand Color Resolution (Sebelum Parse Markdown)
Tentukan warna brand primer dengan urutan prioritas berikut:
1. **Eksplisit dari brand-story-guide.md:**
   - Cari section "Brand Color Palette" atau tabel warna
   - Jika ada HEX warna primer → konversi ke HSL → inject ke --brand-h/s/l
   - Jika ada konflik token yang disebutkan → gunakan yang dilabeli
     "documented brand" (bukan "runtime token")
2. **Industri dari business-knowledge-base.md:**
   - Jika tidak ada warna eksplisit, identifikasi bidang usaha
   - Cocokkan dengan Industry Preset Palette di design-tokens.md §1.2
3. **Default fallback:**
   - Jika tidak bisa menentukan → Venturo Teal (H:186, S:100%, L:34%)

- **Wajib log keputusan** di `reports/build.log`:
  ```
  [COLOR] Source: brand-story-guide.md → #009BAD (documented brand)
  [COLOR] HSL: H=186, S=100%, L=34%
  [COLOR] Conflict noted: runtime token #00A76F differs; using documented brand
  ```
```

### C9. Badge-Title Alignment Consistency

**Masalah:** Beberapa slide punya badge eyebrow left-aligned tapi title centered — visual inconsistency.

**Desain:**

Tambahkan aturan di `skills/builder/SKILL.md` dan update `templates/custom.css`:

Di SKILL.md:
```markdown
### Badge-Title Alignment Consistency Rule
- Badge eyebrow dan slide title HARUS memiliki alignment yang sama:
  - Centered slide → badge juga centered (margin: 0 auto)
  - Left-aligned slide → badge juga left-aligned
- Slide yang wajib centered: Ecosystem (Slide 5), Pricing (Slide 9)
- Slide yang wajib left-aligned: Hero (Slide 1), Problem (Slide 2),
  Solution (Slide 3), Traction (Slide 6)
- Slide opsional mengikuti: Differentiator → left, Social Proof → centered
```

Di `templates/custom.css`, tambahkan:
```css
/* Badge-title alignment consistency */
.slide-ecosystem .slide-header,
.slide-pricing .slide-header,

  text-align: center;
  align-items: center;

.slide-ecosystem .badge-eyebrow,
.slide-pricing .badge-eyebrow,
.slide-social-proof .badge-eyebrow {
  margin-left: auto;
  margin-right: auto;
}
```

### D10. Slug Resolution Protocol

**Masalah:** Orchestrator pakai `<slug>` di semua path tapi tidak ada instruksi bagaimana slug ditentukan. Ini menyebabkan naming inconsistency.

**Desain:**

Tambahkan section baru di `skills/compro/SKILL.md`:

```markdown
## Slug Resolution Protocol

Slug adalah identifier unik per proyek company profile. Ditentukan sekali di Gate 0
dan dipakai konsisten di seluruh pipeline.

### Cara menentukan slug:
1. Ambil nama perusahaan dari heading H1 di `business-knowledge-base.md`
2. Terapkan transformasi:
   - Lowercase semua karakter
   - Ganti spasi dan karakter non-alfanumerik dengan dash (`-`)
   - Hapus dash berturut-turut (`--` → `-`)
   - Trim dash di awal dan akhir
   - Potong maksimal 30 karakter
3. Contoh: "Venturo Pro AI Content Generator" → `venturo-pro-ai-content-genera`
   (lebih baik dipendekkan menjadi `venturo-pro`)

### Konfirmasi slug:
- Tanyakan user: "Slug proyek: `venturo-pro`. Folder output: `compros/venturo-pro/`. OK?"
- User boleh mengubah slug sebelum pipeline dimulai
- Setelah dikonfirmasi, slug TIDAK BOLEH berubah antar phase

### Penggunaan slug:
- `compros/<slug>/index.html`
- `compros/<slug>/compro.md`
- `compros/<slug>/assets/`
- `compros/<slug>/drafts/`
- `compros/<slug>/reports/`
- `compros/<slug>/input/` (symlink atau copy dari root `input/`)
```

### D11. Pipeline Resumability

**Masalah:** Jika pipeline gagal di Phase 3, user harus re-run dari Phase 1 — boros waktu dan token.

**Desain:**

Tambahkan section baru di `skills/compro/SKILL.md` sebelum Gate -1:

```markdown
## Pipeline Resumability

Sebelum menjalankan Gate -1, periksa apakah ada artefak dari run sebelumnya
untuk slug yang dimaksud:

### Auto-detect resume point:
| Artefak yang ditemukan | Resume point | Prompt ke user |
|------------------------|--------------|----------------|
| `compros/<slug>/index.html` ada | Phase 4 (SEO Audit) | "Ditemukan slide deck dari run sebelumnya. Mau langsung audit SEO, atau rebuild dari awal?" |
| `compros/<slug>/drafts/02-final.md` ada | Phase 3 (Build) | "Ditemukan draf final. Mau langsung build slide, atau mulai ulang dari drafting?" |
| `compros/<slug>/drafts/01-draft.md` ada | Phase 2 (Review) | "Ditemukan draf awal. Mau lanjut ke review, atau tulis ulang dari awal?" |
| `compros/<slug>/reports/review-report.md` ada + status REVISION_REQUIRED | Phase 1 (Re-draft) | "Ditemukan review yang meminta revisi. Mau lanjut revisi, atau mulai baru?" |
| Tidak ada artefak | Phase 1 (dari awal) | Lanjut ke Gate -1 seperti biasa |

### Constraint:
- Resume HANYA ditawarkan, BUKAN dipaksakan — user selalu boleh pilih "mulai baru"
- Jika user pilih resume, pastikan input docs masih sama (bandingkan checksum/ukuran)
- Jika input docs berubah sejak run sebelumnya, WAJIB mulai dari Phase 1
```

### D12. Enhanced Test Fixtures

**Masalah:** Test fixtures saat ini sangat minimalis (~1KB total). Tidak representatif untuk input real (~48KB).

**Desain:**

Buat test fixtures yang lebih realistis di `test-fixtures/`:

```
test-fixtures/
├── input/                          # Yang sudah ada (diperkaya)
│   ├── business-knowledge-base.md  # Diperluas ke ~3-5KB dengan data realistis
│   ├── business-audit-report.md    # Diperluas ke ~2-3KB
│   └── brand-story-guide.md        # Diperluas ke ~2-3KB
└── expected/                       # BARU — contoh expected output
    ├── 01-draft.md                 # Contoh draf writer yang baik
    ├── 02-final.md                 # Contoh draf final yang approved
    └── review-report.md            # Contoh review report APPROVED
```

**Content requirement untuk fixtures yang diperluas:**
- Knowledge base harus punya: nama perusahaan, tahun berdiri, bidang usaha, 3+ layanan, 3+ statistik, kontak lengkap (WA, email, web, alamat), pricing 3 tier
- Audit report harus punya: 3+ masalah pelanggan, analisis kompetitor (3+ kompetitor), SWOT ringkas
- Brand story harus punya: tone of voice, target audience, 3+ messaging pillars, warna brand eksplisit, elevator pitch

## 6. Tidak Termasuk dalam Scope v2.2.0

Berikut hal-hal yang sengaja **tidak** dimasukkan:
