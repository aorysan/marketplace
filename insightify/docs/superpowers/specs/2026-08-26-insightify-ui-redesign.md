# Insightify UI Redesign Design Spec

## 1. Goal
Revamp the output HTML generated by the `insightify` plugin to look like a modern Claude Artifact (specifically referencing the "Sistem Antrian MPP" artifact). 
Key requirements:
- High information density with minimal long prose paragraphs.
- Card-based layout with a clean, soft off-white background (`#f9f9f7`), plus full Dark Mode support.
- Retain the floating Table of Contents (TOC) on the side for easy navigation.
- Numbered section headings (e.g., `01`, `02` in blue) for an elegant look.
- Use grids/tables for processes instead of bullet points or sequential text.
- Clean typography using the `Inter` font.

## 2. Approach

### A. Template Changes (`builder` skill)
1. **`styles.css` Update**:
   - Change `body` background to `#f9f9f7`.
   - Update `--color-surface` for cards to pure white with a subtle border (`#e5e7eb`) and soft shadow.
   - Update dark mode color tokens (e.g., `#0b0b0b` for background, `#1a1a19` for surface cards, `#ffffff1a` for borders) to match the Claude Artifact dark theme.
   - Restyle `h2` to include small blue numbering (can be achieved via CSS counters or by instructing the LLM to output numbers, but CSS counters on `h2` are more robust).
   - Add utility classes for modern layouts: `.grid-2`, `.grid-3`, `.artifact-card`, `.badge`, `.status-indicator`.
   - Keep `.toc-container` and `.floating-toc` intact.
2. **`index-html-template.html` Update**:
   - Wrap the main content area in an `.artifact-container` to restrict max-width and center it.

### B. Prompt Changes (`writer` skill)
1. **Markdown Formatting**: 
   - Instruct the LLM in `writer` skill to stop outputting long paragraphs.
   - Demand the use of HTML wrapper tags provided in the CSS (e.g., `<div class="artifact-card">...</div>`, `<div class="grid-2">...</div>`) instead of raw markdown tables or bullet lists, where appropriate, to structure dense information like architecture, endpoints, or processes.
   - Emphasize "high info density, scannability, card-based" in the writing guidelines.

## 3. Data Flow
1. **Planner** -> Extracts info as usual.
2. **Writer** -> Follows new prompt to output Card/Grid structured HTML interleaved with Markdown.
3. **Reviewer** -> Evaluates based on scannability and minimal prose.
4. **Builder** -> Wraps in the new CSS template.

## 4. Open Questions / Ambiguities
- CSS Counters vs Hardcoded Numbers: We will use CSS counters on `section h2` to automatically prefix `01`, `02` to section headers so the LLM doesn't have to manage numbering logic.
- Responsive Design: The grid will collapse to a single column on mobile.

## 5. End State
When `insightify` is run, the resulting `index.html` will have a floating TOC on the left, and a central column of clean, artifact-styled cards presenting the tech specs concisely.
